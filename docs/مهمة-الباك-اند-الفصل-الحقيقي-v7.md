## الأدلة الحية التي تُلزمك (مكررة مختصرة — التفصيل في التقرير)

1. `GET /regions` → 22 محافظة يمنية، **بلا حقل country_code في المخطط نفسه**.
2. `GET /facilities?country_code=966` → **أهمل المعامل وأعاد 21 منشأة** (منها المطعم السعودي #32 «الرياضي» الساكن في منطقة «الجوف» اليمنية).
3. `POST /auth/register` بجوال `0512345678` → **201** ثم `locale/me` → **967/YER** — لا استنتاج بلد من الجوال.
4. `GET /membership/info` بتوكن سعودي → **«3000 ريال يمني» عبر «محفظة جيب»**.
5. `GET /orders/delivery-estimate` عند إحداثيات الرياض → جدول أجرة **اليمن** (`8 أول 3 كم، per_km=2`).
6. `ProductOut/OrderOut` — مبالغ بلا عملة؛ لا يوجد جدول `cities` ولا مسار له.

## المهمة 1 — طبقة البيانات (افعلها أولاً)

```sql
-- 1.1 بلد المنطقة (أساس كل شيء)
ALTER TABLE regions ADD COLUMN country_code VARCHAR(3) NOT NULL DEFAULT '967';
CREATE INDEX ix_regions_country ON regions(country_code);
-- إنشاء 13 منطقة سعودية (الرياض، مكة المكرمة، المدينة المنورة، الشرقية، عسير،
-- القصيم، جازان، نجران، حائل، الباحة، تبوك، الحدود الشمالية، الجوف السعودية)
-- ⚠️ فخ الاسم: «الجوف» اليمنية موجودة (id=1) — الفصل بالـ country_code إلزامي.

-- 1.2 بلد المنشأة + عملة المنتج + عملة الطلب
ALTER TABLE facilities ADD COLUMN country_code VARCHAR(3) NOT NULL DEFAULT '967';
ALTER TABLE products   ADD COLUMN currency VARCHAR(3) NOT NULL DEFAULT 'YER';
ALTER TABLE orders     ADD COLUMN currency VARCHAR(3) NOT NULL DEFAULT 'YER';

-- 1.3 ترحيل
UPDATE facilities f SET country_code = (SELECT country_code FROM regions r WHERE r.id = f.region_id);
UPDATE facilities SET country_code = '966' WHERE id = 32;   -- الرياض ليست في الجوف!
UPDATE products p SET currency = 'SAR'
  WHERE p.facility_id IN (SELECT id FROM facilities WHERE country_code = '966');
-- عملة الطلبات الجديدة تُثبت لحظة الإنشاء (انظر 3.2)
```

**معيار القبول**: `SELECT country_code, COUNT(*) FROM facilities GROUP BY 1;` يظهر سعودياً واحداً على الأقل، ومناطق سعودية = 13.

## المهمة 2 — العقد (API): فلترة حقية + حقول عملة

| # | التغيير | المعيار |
|---|---|---|
| 2.1 | `GET /regions` يقبل `country_code` اختيارياً (بدونه = الكل — توافق خلفي) ويضيف `country_code` لكل عنصر | سعودي يرى 13، يمني يرى 22، بدون معامل يرى 35 |
| 2.2 | `GET /facilities` يقبل `country_code` اختيارياً ويطبقه فعلاً (اليوم يهمله)، و`FacilityOut` يضيف `country_code` + `currency` | `?country_code=966` يعيد المطاعم السعودية فقط |
| 2.3 | `ProductOut` يضيف `currency` | كل منتج يحمل عملته |
| 2.4 | `OrderOut` يضيف `currency` — تُثبت من عملة المنشأة لحظة إنشاء الطلب ولا تتغير بعدها | طلب قديم يظل بعملته حتى لو غيّر التاجر عملته لاحقاً |
| 2.5 | التسجيل: استنتاج البلد من بادئة الجوال (`05…/5…` → 966، `7[01378]…` → 967) وقبول الصيغتين | تسجيل `0501234567` يولّد مستخدماً بـ `country_code='966'` **بدون أي استدعاء يدوي** |
| 2.6 | `POST /otp/request` يدعم أهداف 966 (مزود SMS/واتساب يغطي السعودية) | كود يصل لجوال 05… فعلياً |
| 2.7 | `GET /membership/info` يشتق من بلد المستخدم: سعودي → مبلغ SAR + مسار دفع إلكتروني (مويسر subscription) | استجابة سعودية بلا «محفظة جيب» |
| 2.8 | `GET /orders/delivery-estimate` يختار جدول الأجرة من بلد **المنشأة** (`SA_DELIVERY_*` ↔ `YE_DELIVERY_*`) | تقدير الرياض بقيم SA لا بقيم YE |
| 2.9 | `GET /cards` يفلتر ببلد مناطق البطاقات تلقائياً | سعودي لا يرى بطاقات مناطق يمنية والعكس |

## المهمة 3 — قواعد النظام (معايير لا تُخترق لاحقاً)

1. **كل مبلغ في أي استجابة يحمل `currency`** — لا عملة مستنتجة في الواجهة بعد اليوم.
2. **الأسعار داخل متجر ما بعملة بلد المنشأة دائماً** (السعودي يتصفح مطعماً يمنياً يرى YER) — «سوق المستخدم» يحدد طرق الدفع والعضوية والإشعارات، لا عملة أسعار المتجر.
3. **الجوال + country_code ثنائي فريد** عند التسجيل.
4. **الضريبة**: إضافة `tax_rate` لكل بلد في إعدادات المالية (السعودية 15% — عرض سطر الضريبة متطلب ZATCA؛ اليمن 0) + حقله في `OrderOut` (`tax_amount`) للفاتورة.
5. **مانيفست الكونسول** (دين موثق v6 §7): يشتق `market.currency` و`phone_example` من بلد **مالك المنشأة** — ترقيع ~10 أسطر عند دالة «ريال يمني» في مولد المانيفست.
