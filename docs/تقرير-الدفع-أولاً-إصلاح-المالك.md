**الإصدار بعدها:** 1.6.0 (نفس خط v3.2.2 — إصلاح سلوكي بلا تغيير عقد خادمي)

## 1) ملاحظتك الحرفية والمشخّصة

قالت ملاحظتك: عند فتح التطبيق بحساب سعودي واختيار **«دفع إلكتروني»** والضغط على
**«تأكيد الطلب»** — يظهر فوراً إشعار **«تم استلام طلبك»** وشاشة منبثقة «اطلب الآن /
أكمل بياناتك لتأكيد الطلب» بداخلها «تم استلام الطلب…» وزر **«ادفع الآن»** — وهذا خطأ:
المفروض لا يتم الطلب حتى تظهر شاشة الدفع، وتُدخل بيانات البطاقة، وتتم عملية الدفع
عبر بوابة الدفع للساندبوكس الاختبارية.

**التشخيص الجذري (كان سلوكاً مقصوداً قديماً — وسلوكك هو الصحيح تجارياً):**

الواجهة كانت تتبع «عقد الدفع بعد التأكيد»:
- `CheckoutSheet.tsx` ينشئ الطلب فوراً `payment_method="cash"` ثم يعرض شاشة نجاح
  «تم استلام طلبك» وفيها بطاقة «خطوة أخيرة — الدفع الإلكتروني» وزر «ادفع الآن».
- أي أن **إعلان الاستلام يسبق الدفع** — عكس التوقّع الطبيعي للعميل ولملاحظتك.
- كذلك كانت السلة (صفحة `/cart` والشيت المنبثق) **تُخفي الخيار الإلكتروني فعلياً**:
  تحوّل اختيار «دفع إلكتروني» صامتاً إلى «كاش» بلا أي شاشة دفع.

## 2) العقد الجديد — «الدفع أولاً» (مطبّق في 4 أسطح)

| قبل الإصلاح ❌ | بعد الإصلاح ✅ |
|---|---|
| تأكيد الطلب → إشعار «تم استلام طلبك» + شاشة نجاح → ثم زر «ادفع الآن» اختياري | تأكيد الطلب → **انتقال فوري لشاشة الدفع الآمنة** `/orders/{id}/pay` (مويسر ساندبوكس: بطاقة/Apple Pay/STC Pay) |
| السلة: «دفع إلكتروني» يتحول صامتاً لكاش بلا شاشة دفع | السلة تعترف بالخيار الإلكتروني وتنفّذ نفس العقد: **لا إشعار ولا نجاح قبل الدفع** |
| «تم استلام طلبك» قبل الدفع | «تم استلام طلبك/تم الدفع بنجاح» يظهران **بعد إتمام الدفع والتحقق الحتمي** (`verify → paid`) حصراً |
| نص الزر: «تأكيد الطلب — الدفع بعد التأكيد» | نص الزر: **«الدفع الإلكتروني وإتمام الطلب»** + ملاحظة توقّع: «تُفتح شاشة الدفع الآمنة (مويسر) لإدخال بيانات بطاقتك — يُستلم طلبك بعد إتمام الدفع» |

**ملاحظة عميقة (للأمانة الكاملة):** بوابة مويسر عقدُها الخادمي أن تُتحقق الدفعة مقابل
**طلب قائم** (`POST /finance/orders/{id}/pay/verify` يطابق المبلغ/العملة/الطلب) — لذا
يُنشأ الطلب في الخادم لحظة التأكيد كـ«مرساة دفع» صامتة (`cash`) **بلا أي إعلان
للعميل**، وفور إنشائه ينتقل العميل مباشرة لشاشة الدفع. من منظور العميل:
الضغط → شاشة الدفع → إدخال البطاقة → الدفع → **عندها فقط** «تم الدفع بنجاح / تم
استلام طلبك». وإن تراجع قبل الدفع فلا شيء أُعلن له — الطلب يبقى في «طلباتي» كاش مع
بطاقة «ادفع الآن إلكترونيًا» (وسلوكه كالطلب النقدي العادي حتى يُدفع).

## 5) ماذا يعني هذا لاختبارك التالي (يا كمال)

1. افتح بحسابك السعودي → اختر وجبة → «اطلب الآن» → أكمل الموقع والعنوان.
2. اختر «دفع إلكتروني (بطاقة/Apple Pay)» — لاحظ نص الزر الجديد والملاحظة تحته.
3. اضغط الزر → **ستنتقل مباشرة لشاشة «الدفع الإلكتروني»** (بدون أي إشعار استلام).
4. أدخل بطاقة الساندبوكس: `4201 3201 1111 1010` — تاريخ `12/30` — CVC `123`.
5. أتمم الدفع → تظهر **«تم الدفع بنجاح»** + رقم الطلب — **هنا فقط** يُعلن الطلب.
6. إن أغلقت شاشة الدفع بدون دفع: لا إشعار شيء — تجده لاحقاً في «طلباتي»
   ببطاقة «ادفع الآن إلكترونيًا» (ويُعامل كاش عند الاستلام حتى تدفع).

## 6) بند بيئي واحد موثّق (ليس عيباً في الكود)

بيئة التطوير المحلية (ساندبوكس التطوير) تمنع تحميل `cdn.moyasar.com` (S3 AccessDenied
عن IP بيئة التطوير) — لذا أتممنا إثبات الدفع الفعلي عبر نداءات API مويسر نفسها التي
ينفّذها النموذج المدمج. على أجهزتكم الحقيقية وعلى Vercel لا يوجد هذا القيد إطلاقاً.
